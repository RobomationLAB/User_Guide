# 문서 번역

`ko` 를 기준으로 다른 언어 문서를 만든다. 규칙은 **`docs/TRANSLATION.md`** 에 있다.
이 스킬은 규칙을 복사하지 않는다 — 두 문서가 어긋나면 어느 쪽이 맞는지 알 수 없기 때문이다.

## 시작 전

1. **`docs/TRANSLATION.md` 를 읽는다.** 규칙 1(번역 금지) · 규칙 2(번역 대상)를
   모두 확인한다. 읽지 않고 시작하지 않는다.
2. **`docs/GLOSSARY.md` 를 읽는다.** 용어의 **최종 기준**이다. 읽지 않고 시작하지 않는다.

## 범위 정하기

사용자가 범위를 주지 않았으면 **물어본다.** 한 번에 하나만 처리한다:

- 언어 1개
- 범위 1개 — 카테고리(`common`, `roboids`, `AI`, `CheeseStick`, `program`, `guide`) 또는 마지막의 `index.md`

**카테고리가 최소 단위이자 최대 단위다.**

- 최대인 이유: 44개를 한 번에 하면 뒤로 갈수록 품질이 떨어지고 검증 실패 시
  원인을 찾기 어렵다.
- **최소인 이유: 카테고리 안의 문서들이 서로 링크한다.** 파일 하나만 번역하면
  그 안의 `](Loops)` 같은 링크가 아직 없는 문서를 가리켜 **빌드가 죽은 링크로
  실패한다.** (`common` 만 해도 상호 링크가 4개다) 파일 단위로 쪼개지 않는다.

**`index.md` 는 가장 마지막에 한다.** 이 파일은 **44개 문서 전부를 링크**하므로,
나머지가 모두 번역되기 전에 손대면 없는 문서를 가리키는 죽은 링크가 대량으로
생겨 빌드가 실패한다.

그때까지 `check:i18n` 은 `index.md` 때문에 계속 실패한다. **그건 예상된 잔여물이니
무시하고, 자기 배치 범위의 파일에 문제가 0건인지만 본다.** 마지막에 `index.md` 를
번역하면 비로소 통과한다.

**언어 순서**: `ko` 가 원문, `en` 이 용어 기준이며 `GLOSSARY.md` 가 그 대조에서 추출되어 있다.  
다른 언어는 용어집을 기준으로 작업한다. 
어느 언어가 남았는지는 `npm run check:i18n` 이 알려준다 — 이 파일에 적어두지 않는다.

## 절차

1. 대상 목록을 만든다 — `docs/pages/ko/<범위>/` 의 `.md` 파일들
2. 각 파일마다 `ko` 원문을 읽는다
3. **그 파일의 `<BlockImage>` 이미지를 읽어 실제 블록 라벨을 확인한다.**
   `docs/public/images/<lang>/<module>/<id>.<ext>` 를 Read 로 열면 된다.
   추측하지 않는다 — 예를 들어 `으로 계산` 의 실제 영어 라벨은 `for loop` 가
   아니라 **`count with`** 였다. 라벨이 틀리면 학생이 프로그램에서 그 블록을
   찾지 못한다.
4. `docs/pages/<lang>/<범위>/` 에 같은 파일명으로 쓴다
   - **파일명은 대소문자까지 동일**해야 한다
5. 범위를 다 끝내면 `npm run check:i18n <lang>` 을 실행한다
6. 문제가 나오면 고치고 5번을 반복한다. **자기 범위의 파일이 0건이 될 때까지
   끝내지 않는다.** (`index.md` 항목은 마지막 배치 전까지 남아 있는 게 정상이다)
7. `npm run docs:build` 로 빌드가 통과하는지 확인한다
8. 아래 형식으로 보고한다

## 용어

**`GLOSSARY.md` 를 따른다.** `en` 열은 정답이 아니라 참고다 — 할 일은 en 을 베끼는 게
아니라, 용어집에 실린 ko 표현이 "용어"임을 알아보고 그 언어에서 하나의 표기를 골라
끝까지 쓰는 것이다.

- 같은 블록·UI 요소는 **범위 전체에서 같은 이름**으로 부른다
- `<BlockImage>` 가 있는 섹션은 그 이미지가 해당 언어의 실제 라벨을 보여준다.
  **이미지의 라벨이 산문의 용어보다 권위 있다** (용어집 §12 가 그 사례 모음이다)
- 드롭다운 옵션은 `라벨(코드값)` 형태로 쓴다. 코드값은 번역하지 않는다 (용어집 §3)
- 이미 번역된 다른 문서에서 같은 용어를 쓴 적이 있으면 그것을 재사용한다
  (`grep` 으로 확인한다)
- **새로 정한 용어는 보고에 남기고 `GLOSSARY.md` 에 추가한다**

## 반복되는 정형 구간

`roboids` · `AI` · `CheeseStick` 의 **28개 문서**가 같은 문장 틀을 공유한다.
본문이 완전히 같지는 않고 **제품명만 다르다**:

```
비글(Beagle) 블록을 작업 영역에 추가하면, Python 코드에는 …
햄스터(Hamster) 블록을 작업 영역에 추가하면, Python 코드에는 …
```

이런 구간은 **첫 번역에서 문장 틀을 정하고, 이후 문서에서는 제품명만 바꿔
같은 틀을 쓴다.** 문서마다 다르게 쓰면 28개가 서로 어긋난다.

같은 이유로 통일이 필요한 것들:

| | 규모 |
|---|---|
| `블록을 작업 영역에 추가하면 …` 문장 | 28개 문서 |
| `# 여러 인스턴스가 있는 경우` 코드 주석 | 17개 문서에서 **완전히 동일** — 번역도 하나로 |
| `### 매개변수` 소제목 | 424회 |

작업 중이면 `grep` 으로 앞서 쓴 표현을 확인하고 재사용한다.

## 보고 형식

```
번역: <lang> / <범위>   (N개 파일)

새로 정한 용어
  반복 → repeat
  참 / 거짓 → true / false
  …

check:i18n   통과 / 문제 N건
docs:build   통과

남은 범위: guide, program, roboids, AI, CheeseStick
```

## 하지 말 것

- **규칙을 기억에 의존해 적용하지 않는다.** 매번 `TRANSLATION.md` 를 읽는다
- **`check:i18n` 을 건너뛰지 않는다.** 빌드는 파일명·앵커·이미지 누락을 잡지 못한다
- **범위를 스스로 넓히지 않는다.** 카테고리 하나가 끝나면 보고하고 멈춘다
- **범위를 파일 하나로 좁히지도 않는다.** 카테고리 내 상호 링크 때문에 빌드가 깨진다
- **`<BlockImage>` 라벨을 추측하지 않는다.** 이미지를 열어 확인한다
- **앵커 `{#id}` 를 번역하거나 생략하지 않는다.** 자동 생성 id 는 언어마다 달라져
  문서 간 링크가 깨진다
